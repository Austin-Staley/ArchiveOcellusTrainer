# Scenarios and their oracles

This page lists, for each mechanic, the Vitest scenario and the browser scenario that prove it, the input each one sends, and where its expected value comes from. Use it before moving code between owners. A mechanic whose rows lose a scenario, or whose oracle becomes a value read from the code under test, has lost its safety net. Change this page in the same pull request that changes a scenario.

## Input kinds

- `click`: a real `mousedown` on the trainer's canvas at the tile's 2D position. `drill.click(tile, { ctrlKey })` in `src/content/ocellus/tests/drill.ts` sends it. The SDK's ClickController resolves the tile, queues the order through InputController, and the next `world.tickWorld()` hands it to `Player.moveTo`. The fight log's `walk-ordered` input proves which tile the click resolved to.
- `page`: a real DOM click or key press on the mounted page through `loadPage` in `page.tsx`.
- `order`: a direct `Player.moveTo` through `drill.walkTo` or `drill.player().moveTo`. It skips ClickController, the input queue and the Control-key mapping.
- `none`: no player input. The URL's drill options and real World ticks drive the run.
- Browser: `scripts/verify.sh browser` sends real mouse input through agent-browser, and a Control-click through CDP's Input domain. Every browser scenario runs in 3D.

Every Vitest scenario built on `startDrill` sets `world.getReadyTimer = 0`, because the SDK counts GET READY down only in its browser loop. The section on tests that bypass real paths lists it with the other bypasses.

## Oracle sources

- `data`: a value in `src/content/ocellus/js/OcellusTimings.ts`, named by its `OCELLUS_P4` key. Each value there carries its own footage, wiki, cache or owner source.
- `wiki`: an Old School RuneScape Wiki page. The data file cites the pages its values come from.
- `hand`: worked out by hand from `data` or `wiki` values, with the working given here.
- `seeded`: the output of a seeded roll, pinned from a passing run. Only its bounds are independent, and they come from `data`.

## Tests that bypass real input or real ticks

None is deleted in this slice. Each stays until the slice that replaces its API, which then moves the claim onto real input and deletes the bypass. An entry that names no slice belongs to a mechanic the approved migration does not move, and it keeps its bypass until a slice is scoped for it. A scan of the TypeScript syntax tree of every `*.test.ts` and `*.test.tsx` file in `src/content/ocellus/tests/` produced the counts and lines below.

- **GET READY write.** `startDrill` in `drill.ts`, so every Vitest scenario above. Also `drill.restart`, `U1-cycle.test.ts:114`, `RunResult.test.tsx:15` and `SettingsMenu.test.tsx:76`. Slice 2 moves the countdown into the world step. `drill.restart` also skips the Restart button, because it calls `region.reset` directly, in `OcellusRegion.test.ts:25` and `:97` and `U1-cycle.test.ts:140`. No slice moves restarts.
- **Direct `Player.moveTo` orders.** `drill.walkTo` and `drill.player().moveTo` in `BossFootprint.test.ts` (10), `OcellusRegion.test.ts` (8), `U8-floor-holes.test.ts` (8), `U3-lifeforce-orb.test.ts` (8), `U2-floor.test.ts` (7), `U4-explosions.test.ts` (4), `Invincible.test.tsx` (3), `U4-dodge-attack-speed.test.ts` (2), `U1-cycle.test.ts` (2), and one each in `U1_5-loadouts.test.ts`, `U5-transition.test.ts`, `U6-overheads-heals-rifts.test.ts` and `U8-boss-defence.test.ts`. `drill.playCorrectlyTo` also orders with `moveTo`, in `BossFootprint.test.ts`, `BossStates.test.ts`, `U1-cycle.test.ts`, `U3-lifeforce-orb.test.ts` and `U5-transition.test.ts`. A floor tile in view converts to `drill.click`. A tile under the visible boss stays with the browser. The slice that moves each mechanic converts its file: orbs in slice 5, then explosions, floor and rifts in slice 6.
- **Direct prayer toggles.** `drill.pray` calls `toggle` on the prayer, skipping the prayer tab click, in `U1_5-loadouts.test.ts`, `U1-cycle.test.ts`, `U3-lifeforce-orb.test.ts`, `U5-transition.test.ts` and `U6-overheads-heals-rifts.test.ts`. `drill.playCorrectlyTo` toggles the same way on each transition tell, in the files listed above.
- **Direct inventory clicks.** `drill.clickInventory` and `item.inventoryLeftClick` skip the side-panel click. Used in `U1_5-loadouts.test.ts`, `U4-dodge-attack-speed.test.ts`, `U6-overheads-heals-rifts.test.ts`, `U7-supplies-and-names.test.ts` and `U8-boss-defence.test.ts`.
- **Direct attacks.** `player().setAggro(target)` picks the target with no click on it, 13 times: `U6-overheads-heals-rifts.test.ts` (4), `U1_5-loadouts.test.ts` (3), `U4-dodge-attack-speed.test.ts` (2), `U8-boss-defence.test.ts` (2), `Invincible.test.tsx:146` and `U1-cycle.test.ts:251`. In 2D, a `drill.click` on a tile of the visible boss attacks him, as the phase activation case above records. Slice 4 converts the seeded combat test in `U1-cycle.test.ts`. Slice 6 converts the explosion dodges in `U4-dodge-attack-speed.test.ts`, and all of `U6-overheads-heals-rifts.test.ts` with the rifts. No slice moves loadouts, boss defence or Invincible.
- **Direct special attacks.** An assignment to `player().useSpecialAttack` skips the click on the special attack bar, 8 times: `U1_5-loadouts.test.ts` (3), `U8-boss-defence.test.ts` (3) and `U6-overheads-heals-rifts.test.ts` (2). Slice 6 converts the `U6` cases with the rifts. No slice moves loadouts or boss defence.
- **Direct attack styles.** `AttackStylesController.controller.setWeaponAttackStyle` skips the click on the combat tab, in `U1_5-loadouts.test.ts:115`, `:128` and `:133`. No slice moves loadouts.
- **Direct key binding start.** `SettingsControls.instance.startKeyBinding("inventory")` skips the click on the inventory key binding button in the settings panel, in `U7-keybinds.test.tsx:26` and `:47`. No slice moves key bindings.
- **Synthetic hits.** `drill.hit` adds a projectile with a chosen damage: six in `U1-cycle.test.ts` and three in `U6-overheads-heals-rifts.test.ts`. `hitBoss` in `RunResult.test.tsx:28` adds one the same way to end the run. Slice 4's binding replaces them with real attacks on the seeded stream.
- **Direct state writes.** `region.invincible` in `Invincible.test.tsx` (7) and `U1-cycle.test.ts:8`. `currentStats.strength` in `U1_5-loadouts.test.ts:107` and `:116`. `currentStats.prayer` in `U7-supplies-and-names.test.ts:48`. `Settings.playsAudio` and `Settings.playsAreaAudio` in `Cues.test.ts:61` and `:62`, and `Settings.inventory_key` in `U7-keybinds.test.tsx:32`, leave stale values in memory before a reload. A browser reload rebuilds `Settings` from storage instead. No slice moves any of these writes.

Some test calls only observe. The spies on `playAnimation` in `U1-cycle.test.ts`, on `SoundCache.play` in `Cues.test.ts`, on `initialiseRegion` in `RunResult.test.tsx` and `SettingsMenu.test.tsx`, and on `incomingAttackRollModifiers` in `U8-boss-defence.test.ts` call through to the real code. The animation listener in `U6-overheads-heals-rifts.test.ts:255` records sequences.

Some replace a browser or engine boundary. `Cues.test.ts` stubs `navigator.userAgent` to pick the platform, and clears the SDK's cached answer in `Settings._isMobileResult`. `WhatsNew.test.tsx` stubs `Storage` reads and writes to block one key. `U1-cycle.test.ts:248` swaps the SDK's random source with `Random.setRandom` and restores it.

`U1_5-loadouts.test.ts:50` and `:130` add `MaxRollDummy` through `region.addMob`. It is a `TestNpc` that forces maximum rolls, so the loadout tests read max hits without a seed.
